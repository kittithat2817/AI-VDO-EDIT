# ทำซับ CapCut ผ่านไฟล์

ทำซับข้อความธรรมดาที่แก้ไขต่อได้ใน native draft ของ CapCut ด้วย workflow **ระบุงาน → ตรวจเสียงและไทม์ไลน์ → ถอดคำพูด → แบ่งวลีและจับเวลา → วางซับ → ตรวจ** เป้าหมายคือคำพูดถูกต้องและซิงค์กับเสียง ไม่ใช่การตกแต่งซับ

## ข้อตกลงของสกิล

- **ทำผ่านไฟล์เท่านั้น ห้ามเปิด ปิด หรือควบคุม CapCut** รวม UI automation, deep link หรือคำสั่งเบื้องหลังที่สั่งแอป อ่านไฟล์และวิเคราะห์สื่อบนดิสก์ได้ ไม่ fallback ไปควบคุมโปรแกรม
- ค่าเริ่มต้นเป็นซับครบตามคำพูด เมื่อผู้ใช้หรือโปรไฟล์ที่เลือกกำหนด selective/keyword ให้อ่าน [ซับเลือกเน้น](references/selective-captions.md) ก่อนแบ่ง cue คง transcript เต็มไว้แยกจากข้อความขึ้นจอ รักษาคำปฏิเสธ เงื่อนไข ตัวเลขและชื่อเฉพาะ ไม่เพิ่มคำกล่าวที่ไม่มีหลักฐาน
- **ไม่เพิ่ม template, preset สำเร็จรูป, animation, Pop, Typing, Overshoot หรือเอฟเฟกต์ตกแต่ง** ใช้ native text/caption แบบธรรมดาที่อ่านโครงสร้างได้
- รับสไตล์ สี ขนาด และตำแหน่งจาก Subtitle Preview ในคำสั่งของงานนั้น ถ้าผู้ใช้ระบุซับธรรมดาต้นแบบหรือสไตล์เพิ่มเติม ให้ใช้ค่าเหล่านั้นเฉพาะส่วนที่ระบุ งานเพิ่มใหม่ที่ไม่มีสไตล์กำหนดให้เลือกพื้นฐานอ่านง่ายและแจ้งสมมติฐาน ไม่เปลี่ยนรูปแบบซับอื่นทั้งโปรเจกต์
- งานซับอย่างเดียวห้ามตัด ย้าย เปลี่ยนความยาว/speed/effects ของภาพหรือเสียง และห้ามยืด draft เพื่อให้ซับพอดี
- ตรวจ draft และชุดซับเป้าหมายจากคำขอ ไม่เลือกโปรเจกต์ล่าสุด ไม่ reuse cue text/time/track/material IDs จากงานก่อน หากหลายเป้าหมายกำกวมให้ถามก่อนเขียน
- งานแก้ซับเดิมแก้เฉพาะชุดที่ผู้ใช้ระบุ งานเพิ่มซับให้สร้างชุดแยกโดยไม่ทับ/ซ่อน/ลบชุดอื่นเอง ไม่บังคับให้ track บนสุดหรือใช้หมายเลขเดิมทุกงาน

## 1. ตรวจไฟล์และขอบเขต

อ่าน [ความสมบูรณ์ของไฟล์และข้อความ CapCut](references/draft-integrity.md) ก่อนเขียน ตรวจ draft identity/revision, รูปแบบ/version, FPS, ขนาดภาพ, timebase, tracks/segments/materials, source/target timing, gaps และ speed บันทึก snapshot ของภาพ เสียง และซับนอกขอบเขต

ระบุภาษาเสียงและช่วงที่ต้องทำจากบริบท ไม่สมมติภาษาไทยทุกงาน หากขอแปลต้องทราบภาษาปลายทาง มิฉะนั้นทำตามภาษาที่พูดจริง ใช้ไฟล์และสื่อที่ผู้ใช้อนุญาต

รองรับทั้ง Timeline, ช่วง In–Out, จาก In ถึงท้าย และจากต้นถึง Out ใช้ขอบเขตบน Timeline เป้าหมาย ตรวจลำดับจุดกับความยาวจริงของ draft อ่าน `MM:SS` และ `HH:MM:SS` โดยให้เลขหลังจุดเป็นเศษวินาที ตรวจ `HH:MM:SS:FF` กับ FPS และ timebase จริงก่อนแปลง ถ้าเวลาไม่ถูกต้องหรือขอบเขตไม่ชัด ให้ขอจุดที่ถูกต้องก่อนเขียน รักษาซับนอกช่วงไว้

ใช้โครงสร้าง native text/caption ที่อ่านและตรวจได้ของ draft รุ่นนั้น หากมีเพียงเทมเพลตแอนิเมชัน ห้าม clone ทั้งชุดแล้วเรียกว่าซับธรรมดา ต้องสร้าง plain text จากต้นแบบที่รองรับ หรือเอา dependencies ของเอฟเฟกต์ออกเฉพาะเมื่อเข้าใจโครงสร้างและตรวจได้ หากไม่มีฐานที่เชื่อถือได้ให้หยุดเขียนและขอไฟล์ตัวอย่างซับธรรมดา ไม่เปิด CapCut สร้างให้เอง

## 2. ถอดคำพูดและซิงค์

- ฟังเสียงหรือใช้ transcript ที่ตรวจได้กับไฟล์จริง รักษาชื่อเฉพาะ ตัวเลข คำปฏิเสธ และคำลงท้าย ระบุช่วงฟังไม่ชัดแทนการเดา
- ถอดจากเสียงในลำดับไทม์ไลน์ปัจจุบัน หากเริ่มจาก source transcript ต้อง map ผ่าน source in/out, cuts, repeats, gaps และ speed ก่อน อย่าใช้เวลา source เป็นเวลา draft โดยตรง
- ถ้า retime ไม่เป็นเส้นตรงและอ่าน mapping ไม่ได้ ให้หยุดการยืนยันเวลาช่วงนั้น ขอเสียงของไทม์ไลน์/ข้อมูลที่เพียงพอ ไม่เดา offset หรือแอบเปิดแอปเพื่อ export
- แบ่งตามหน่วยความหมายและจังหวะพูด ให้เวลาอ่านพอ ใช้เพดานคำเมื่อผู้ใช้/โปรไฟล์ระบุ ภาษาไทยไม่ใช้ช่องว่างหรือ ASR subword นับคำอย่างเดียว
- จัดตามเพดานคำต่อบรรทัดที่ระบุโดยขึ้นบรรทัดที่ขอบคำภายใน cue เดียวกัน ตรวจเพดานคำต่อ cue และจำนวนบรรทัดของโปรไฟล์แยกกัน หากกำหนดบรรทัดเดียวและคำใน cue เกินเพดานต่อบรรทัด ให้แบ่ง cue ตามความหมายและจังหวะเสียง คำตอบที่จบความในคำเดียว เช่น “ใช่” ขึ้นเดี่ยวได้
- ตรวจบรรทัดกับฟอนต์และพื้นที่ภาพจริง รักษาชื่อเฉพาะและหน่วยคำ โหมด full รักษาคำพูดครบ โหมด selective เลือกสารตามโปรไฟล์ก่อนจัดบรรทัด
- ให้ cue เริ่ม/จบสัมพันธ์กับคำพูดและหยุดในช่วงที่ไม่มีคำพูด ตรวจการซ้อนเฉพาะที่ตั้งใจ เช่น ผู้พูดพร้อมกัน ไม่อ้างว่าซิงค์จาก silence detection อย่างเดียว
- เก็บ cue list ที่มีข้อความ ภาษา source/target timing และข้อสงสัย พร้อม draft revision เมื่อผู้ใช้แก้ rough-cut ให้คำนวณช่วงที่เปลี่ยนใหม่

## 3. วางซับและตรวจ

ทำ staging ของ draft ก่อน วาง text materials และ segments ด้วย IDs/references ที่ถูกต้องตามรูปแบบจริง โดยไม่มีการอ้างถึง animation/template ที่เพิ่มขึ้น ตรวจข้อความสั้น ยาว และอักขระของภาษาที่ใช้ก่อนขยายทั้งชุด

เมื่อใช้ Subtitle Preview ให้เทียบขนาดฟอนต์จากสัดส่วนความกว้างเฟรมและตำแหน่งแนวตั้งจากขอบบนถึงกึ่งกลางซับกับเฟรมและฟอนต์จริง รักษาสัดส่วนภาพของ Timeline ใช้ตัวอักษรเรียบ กล่องเข้ม หรือขอบเข้มผ่านฟิลด์ข้อความธรรมดาที่ตรวจได้ใน draft ตรวจคำต่อบรรทัด จำนวนบรรทัด และขอบซับของตัวอย่างสั้นและยาวใน staging แจ้งผู้ใช้ก่อนเขียนจริงหากค่าที่ขอรองรับไม่ครบหรือจำเป็นต้องปรับเพื่อให้อ่านได้

สำรองก่อนเขียนทับตามปกติ เว้นแต่ผู้ใช้สั่งไม่ต้องสำรอง ตรวจ fingerprint ก่อนแทนที่ หากไฟล์เปลี่ยนให้โหลดใหม่และปรับแผน ไม่ทับการแก้ล่าสุด

ตรวจคำพูดและการสะกด timing, bounds, gaps, line breaks, font availability, style ranges และ material references เทียบ snapshot ว่าภาพ เสียง ระยะเวลา และซับนอกขอบเขตคงเดิม Track index ที่เปลี่ยนจากการเพิ่มแทร็กไม่ใช่เหตุให้ละเลย identity

ส่งพาธ draft ชื่อชุด/แทร็ก จำนวน cue จริง ช่วงที่ทำ และผลตรวจ การอ่าน JSON ผ่านไม่ยืนยันการแสดงผลใน CapCut ให้ระบุว่ายังไม่ได้เปิด/render ในแอป ไม่ส่งเพียง SRT แล้วอ้างว่าใส่ซับในโปรเจกต์แล้ว; สร้าง SRT เป็นผลเสริมหรือผลบางส่วนได้เมื่อเหมาะกับคำขอและต้องแจ้งชัด

## ใช้ซ้ำกับคลิปต่อไป

อ่าน [โปรไฟล์ซับที่ใช้ซ้ำได้](references/reusable-workflow.md) เมื่อขอใช้วิธีเดิมหรือเก็บแนวทาง นำหลักการแบ่งวลี การอ่าน และรูปแบบข้อความพื้นฐานกลับมาใช้ ส่วน transcript, cue timing, media paths และ material IDs ต้องผูกกับคลิปใหม่ทุกครั้ง
