# SOP เครื่องหมาย-อย. สำหรับงานทดลองและขายสินค้า

คำสั่งผู้ใช้วันที่ 5 พฤศจิกายน 2026: ใช้กับทุกคอนเทนต์แนวทดลองหรือขายสินค้าของผู้ใช้ใน workflow นี้ รวมงานที่ไม่ได้เกี่ยวกับแอลกอฮอล์

## แหล่งที่ใช้

ใช้ preset ชื่อ **`เครื่องหมาย-อย.`** ตามที่ผู้ใช้ระบุ อยู่ใน CapCut **สื่อ → ของคุณ → ค่าล่วงหน้า** ชื่อนี้เป็นชื่อ preset ไม่ใช่คำสั่งให้พิมพ์ข้อความชื่อเดียวกันลงคลิป

ทำผ่านไฟล์: ค้นข้อมูล preset และ resource ที่เก็บบนดิสก์ หรือใช้ instance ที่ตรวจว่าเป็น preset นี้ในโปรเจกต์ปัจจุบัน การระบุตำแหน่ง UI ใช้เป็นข้อมูลค้นหาเท่านั้น ไม่เปิดหรือควบคุมแอป การอนุญาตนี้ครอบคลุม preset นี้และไฟล์ประกอบที่จำเป็น แม้ยังไม่ได้อยู่ใน Timeline; ไม่ขยายเป็นการใช้คลังสื่ออื่นทั้งหมด

ตรวจชื่อและโครงสร้าง preset จริง รวมข้อความ ภาพ layer/compound, fonts และ resources ที่พึ่งพา เก็บองค์ประกอบที่จำเป็นครบ ไม่ใช้ภาพ PNG หนึ่งชิ้นแทนทั้งชุดโดยยังไม่ตรวจ ไม่คัดลอก UUID/path/เลขผลิตภัณฑ์จากงานก่อนมาเป็นค่าถาวร ตรวจว่าเนื้อหาภายในตรงกับสินค้าปัจจุบันก่อนใช้ หากมีหลายรุ่นที่ชื่อเหมือนกัน ให้เลือกจากหลักฐานที่ตรงสินค้าหรือถามเฉพาะจุดที่แยกไม่ได้

## ในแผนของ planner

งานทดลอง/ขายสินค้าที่ใช้ SOP นี้ต้องมี requirement `product_mark` เสมอ งานทั่วไปใช้ profile `user-product-content`; งานแฮมแฮงค์ที่ใช้ SOP เดิมยังใช้ `hamhang-experiment` และเก็บข้อบังคับเดิมครบ อ่านรายละเอียดสินค้านั้นเพิ่มเติมเฉพาะเมื่อเกี่ยวข้อง

บันทึก preset name, แหล่งที่ค้นได้จริง, revision/hash ถ้ามี, resource paths, asset/material mapping และช่วงแสดงที่วางแผนใน job state ใช้ช่วงตาม SOP/บรีฟและความอ่านชัด ไม่ถือว่าคำว่า “ทุกคอนเทนต์” หมายถึงต้องแสดงทุกเฟรม หากไม่มี preset/ยัง resolve ไม่ได้ ให้คงรายการเป็น `missing` พร้อมเหตุผลและแนวทางเติม งานจัดเรื่องส่วนอื่นทำต่อได้

การพบ preset ในคลังยังไม่ใช่ `satisfied`: ต้องผูกกับโปรเจกต์และมีผลตรวจ instance จริงก่อน เก็บ source provenance ของ preset ที่อนุญาตใน inventory และ handoff. ข้อความเลขอ้างอิง/หมายเหตุเฉพาะสินค้าให้ใช้ของสินค้านั้น ไม่สืบทอดจากสินค้าเก่าหรือถือว่าทุกงานต้องมีคำเตือนแอลกอฮอล์

## ในงานของ script-edit และ QC

นำ preset ที่ตรวจได้มาใช้ หรือรักษา instance เดิมที่ถูกต้อง หลีกเลี่ยงการวางซ้ำหากมีอยู่แล้ว รักษาองค์ประกอบ ข้อความ และรูปแบบของ preset; ปรับตำแหน่ง/ขนาด/ระยะเวลาเท่าที่จำเป็นให้เหมาะกับงานและอ่านได้ เมื่อ native schema หรือ resource ยัง resolve ไม่ได้ ให้คง missing และรายงานส่วนที่ขาด ไม่สร้างเครื่องหมาย/เลข/ข้อความแทนเอง

ก่อนรายงานผ่าน SOP ตรวจจาก staging และ live read-back ว่า instance อยู่ใน Timeline จริง ถูกช่วง/ตำแหน่งตามแผน resources ครบ ข้อความและองค์ประกอบไม่หาย ไม่ซ้อนซ้ำหรือบังเนื้อหาสำคัญ เก็บผลแยกจากการรับรอง native render. `validate_plan.py` ตรวจว่ารายการบังคับไม่หายและมี asset binding; ไม่รับรองหน้าตาหรือความตรงของ preset โดยลำพัง
