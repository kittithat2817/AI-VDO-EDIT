# โปรไฟล์วิธีตัดต่อสำหรับคลิปต่อไป

อ่านเมื่อผู้ใช้ขอใช้วิธีเดิม บันทึก workflow หรือทำงานต่อเป็นซีรีส์ กระบวนการหลักใช้ซ้ำได้ แต่จังหวะและภาพต้องเหมาะกับเนื้อหาใหม่

## Workflow profile

เก็บชื่อ/version และขอบเขต (ซีรีส์/แบรนด์/ประเภทงาน), เป้าหมายการเล่าเรื่อง, โครงเรื่องแบบปรับได้, เกณฑ์เลือก take, pacing, หลักการใช้ภาพประกอบ/motion/เสียง และเกณฑ์ตรวจ บันทึกบทบาทสื่อกับคุณสมบัติที่ต้องการ ไม่ผูกกับ clip ID หรือ track index เก็บที่มาของความชอบว่าเป็นคำสั่งผู้ใช้หรือสมมติฐาน

ไม่บรรจุข้อความเก่า เวลา source/target, พาธ draft, IDs, render settings เฉพาะคลิป หรือสิทธิ์ให้ใช้สื่อของลูกค้ารายหนึ่งเป็นค่าที่ทำงานข้ามโปรเจกต์ ข้อกำหนด file-only ของสกิลยังใช้เสมอ

## Job state

เก็บแยกเฉพาะงาน: draft path/fingerprint/revision/schema, inventory, timebase/FPS, source/target ranges, media/material/track binding, แผนตัด, ฟีดแบ็ก และผลตรวจ รวมขั้นตอนที่ทำแล้วและส่วนที่ยังติดขัด

## บันทึกและนำไปใช้

1. อ่านโปรไฟล์ที่ผู้ใช้เลือกหรือไฟล์ที่อยู่ในขอบเขตงาน หาก “เหมือนคลิปก่อน” ระบุไม่ได้ ให้ถามงานอ้างอิงนั้น ไม่เลือก draft ล่าสุดเอง
2. เก็บโปรไฟล์ที่จำเป็นในโฟลเดอร์ workflow ของงาน เช่น work/workflows/<profile-name>.md และ job state แยกกัน ส่งพาธจริงให้ผู้ใช้อ้างครั้งหน้า หากมีคลังกลางที่กำหนดให้ใช้คลังนั้น ไม่เขียนลงโฟลเดอร์สกิลอัตโนมัติ
3. สำหรับคลิปใหม่ เทียบบรีฟกับโปรไฟล์ ระบุสิ่งที่ใช้ต่อและสิ่งที่ถูกแทนที่ จับคู่บทบาทกับสื่อ/เอฟเฟกต์ CapCut ที่มีจริงแล้ววางช่วงเวลาใหม่ทั้งหมด
4. ตรวจ schema, FPS, aspect ratio, ภาษา และทรัพยากรของงานใหม่ ไม่ถือว่าไฟล์อ่านได้เพราะงานก่อนอ่านได้
5. เก็บฟีดแบ็กเฉพาะช็อตใน job state ยกระดับเป็นโปรไฟล์เมื่อผู้ใช้ระบุให้ใช้กับคลิปถัดไป ไม่เปลี่ยนสไตล์ของงานอื่นตามเอง

ตัวอย่าง: นำหลัก pacing ของรีวิวแนวตั้งไปใช้กับสินค้าใหม่ได้ แต่ต้องเลือกภาพหลักฐานและซิงค์เสียงใหม่; งานสัมภาษณ์ที่ขอจังหวะช้าต้องปรับจากบรีฟ ไม่ลอกจังหวะสั้นของรีวิวทุกช่วง
