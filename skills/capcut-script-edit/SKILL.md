# ตัดต่อ CapCut ผ่านไฟล์

ทำโปรเจกต์ CapCut ที่ผู้ใช้แก้ไขต่อได้ด้วย workflow **รับโจทย์ → สำรวจสื่อ → วางเรื่อง → ตัด → ตรวจ → ส่งมอบและเก็บวิธีทำงาน** ปรับให้เหมาะกับแต่ละคลิป ไม่ผูกกับโปรเจกต์ล่าสุดหรือสูตรภาพ/เสียงแบบเดียว

## ข้อตกลงของสกิล

- ทำผ่านไฟล์เท่านั้น **ห้ามเปิด ปิด หรือควบคุม CapCut** รวม UI automation, keyboard/mouse, deep link, app launch และคำสั่งสั่งแอปเบื้องหลัง อ่านไฟล์และวิเคราะห์สื่อด้วยเครื่องมือบนดิสก์ได้ ไม่ใช้การควบคุมแอปเป็น fallback
- เป้าหมายคือ native draft ของ CapCut ที่แก้ไขได้ ไม่เปลี่ยนไปส่งเฉพาะวิดีโอหรือโปรเจกต์โปรแกรมอื่นแล้วอ้างว่าทำครบ
- ใช้คำสั่งปัจจุบันก่อนโปรไฟล์ที่ผู้ใช้เลือก แล้วจึงใช้หลักฐานและสมมติฐานที่แจ้งไว้ ไม่สืบทอดข้อจำกัดเฉพาะคลิปเก่าเป็นกฎทุกงาน
- ไม่ใช้พาธ project/draft ID, ชื่อคลิป, track index, source ranges หรือเวลาจากงานก่อนโดยอัตโนมัติ ตรวจเป้าหมายใหม่ทุกครั้ง ถ้าระบุไม่ได้ชัดให้ถามก่อนเขียน
- คงสกิลและโปรเจกต์ Premiere แยกต่างหาก ไม่ใช้เครื่องมือ Premiere แก้ CapCut หรือแปลงเทมเพลต/เวลา/โครงสร้างไฟล์โดยสมมติว่าเข้ากันได้
- การเรียกสกิลอนุญาตงานตามบรีฟ ไม่เพิ่มขั้นรอ Approved ทุกงาน ถ้าข้อมูลสำคัญขาด ให้ถามเฉพาะจุดและทำส่วนที่ไม่ขึ้นกับคำตอบต่อ

## 1. รับบรีฟและตรวจความพร้อมของไฟล์

อ่านเป้าหมาย ผู้ชม ประเภทคลิป ภาษา สัดส่วนภาพ ความยาวหรือจังหวะที่ต้องการ สคริปต์/แนวเรื่อง แหล่งสื่อ ผลส่งมอบ และขอบเขตแก้จากบริบท ไม่บังคับให้ทุกงานมีสคริปต์หรือบทพูด

กำหนดว่าจะปรับ draft เดิมหรือสร้างฉบับใหม่ตามคำขอ งานใหม่ต้องมีโครงสร้างต้นแบบที่รองรับและตรวจได้ ไม่สร้าง draft ว่างด้วย field ที่เดาขึ้นเอง ถ้าไม่มีต้นแบบให้ขอไฟล์โปรเจกต์ตัวอย่างหรือรอผู้ใช้เตรียม ไม่เปิด CapCut ให้เอง

ก่อนแก้ อ่าน [ความสมบูรณ์ของไฟล์ CapCut](references/draft-integrity.md) ค้น draft ในโฟลเดอร์งานหรือ registry ที่เข้าถึงได้โดยใช้เป็นข้อมูลค้นหา ไม่ใช้รายการล่าสุดเป็นหลักฐานว่าเป็นเป้าหมาย ตรวจรูปแบบ/version, fingerprint, media paths, tracks/segments/materials, FPS, ขนาดภาพ, timing, speed และ audio links ของ draft จริง

หากรูปแบบอ่านไม่ได้ ถูกเข้ารหัส หรือมีโครงสร้างจำเป็นที่ยังอธิบายไม่ได้ ให้หยุดเฉพาะขั้นเขียน แจ้งสิ่งที่ขาด และส่งผลวิเคราะห์/แผนที่ทำได้ ห้ามเปลี่ยนไปควบคุมโปรแกรมหรืออ้างว่าแก้สำเร็จ

## 2. สำรวจสื่อและเวอร์ชันล่าสุด

- ใช้สื่อในโปรเจกต์ โฟลเดอร์ หรือคลังที่ผู้ใช้อนุญาต ตรวจไฟล์จริงก่อนอ้างว่าออนไลน์ ไม่เพิ่มสื่อภายนอกโดยพลการ
- ดูภาพและฟังเสียงที่ใช้ เลือกบทบาทตามเนื้อหา เช่น บทพูด ภาพประกอบ การสาธิต ดนตรี หรือบรรยากาศ ไม่บังคับว่าต้องมีกล้องและ screen recording
- ใช้เสียง/transcript เพื่อเข้าใจคำพูด waveform/silence ช่วยหาจังหวะได้แต่ไม่ใช่หลักฐานเนื้อหา งานไม่มีเสียงพูดใช้การกระทำ ภาพ และดนตรีนำ
- เมื่อมีเสียงบอกบท/เทคซ้ำ ตรวจบทบาทผู้พูดร่วมกับเสียง ภาพ และข้อมูลผู้ใช้ เก็บช่วงห้ามใช้และช่วงผู้พูดจริงที่เลือก ASR ไม่ยืนยันบทบาท หลีกเลี่ยงการตัดหรือ mute เสียงผู้ทำคอนเทนต์ไปพร้อมเสียงทีมงาน ถ้าเสียงทับกันให้หา clean take ที่รักษาสารได้
- เมื่อ resume ตรวจไฟล์ล่าสุดเทียบ checkpoint ผู้ใช้อาจแก้ไทม์ไลน์แล้ว เมื่อเป็นคลิปใหม่สร้าง job state ใหม่และจับคู่สื่อใหม่ ไม่ replay การแก้ของงานก่อน

## 3. วางเรื่องและตัดตามชนิดคลิป

ทำแผนสั้นที่ผูกช่วงเนื้อหาหรือการกระทำกับ source range, เวลาไทม์ไลน์, เสียง และสิ่งที่แก้ พร้อมระบุส่วนที่ไม่มีสื่อรองรับ เลือกวิธีตามบรีฟ:

| งาน | หลักการ |
| --- | --- |
| พูด/สัมภาษณ์ | รักษาสาระ บริบท และจังหวะพูด ใช้ภาพประกอบเมื่อช่วยให้เข้าใจ |
| รีวิว/เดโม | แสดงขั้นตอนและหลักฐานจริง ให้เวลาอ่านและเห็นผลลัพธ์ |
| เรื่องเล่า/ท่องเที่ยว | จัดลำดับเหตุการณ์และความต่อเนื่องของภาพกับเสียง |
| Montage/สินค้า/ดนตรี | ใช้จังหวะและการกระทำของภาพ ไม่บังคับ voiceover |
| แก้ฟีดแบ็ก | ระบุจุดแก้และผลต่อเวลา รักษาส่วนที่ไม่เกี่ยวข้อง |

- วางโครงก่อนเก็บรายละเอียด ไม่กำหนดจำนวนช็อต ความยาว หรือการใช้ zoom/split screen จากคลิปเก่า
- ใช้ motion/transition/เพลง/SFX ตามบรีฟและทรัพยากร CapCut ที่ตรวจได้ หากต้องแทนสไตล์สำคัญที่ไม่มี ให้แจ้งความต่างและถามก่อน ไม่สร้าง effect payload ที่ไม่ทราบรูปแบบ
- รักษาซิงค์ source bounds และเสียงหลัก ไม่เพิ่มเสียงกล้องซ้ำโดยไม่ตั้งใจ ปรับเพลงใต้บทพูดเมื่อมีบทพูด ไม่บังคับสูตรนี้กับ montage
- หากเวลาคลิปเปลี่ยน ให้ปรับเสียง กราฟิก และซับที่เกี่ยวข้องตาม mapping ของแต่ละช่วง ไม่เลื่อนทั้งหมดด้วย offset เดียวเมื่อมีหลายจุดตัด
- รับ excluded spans, protected ending และ caption profile จากแผนหรือบรีฟ จองช่วงเสียงปิดที่ต้องมีไว้ก่อนย่อ และตรวจว่าคำพูดสุดท้ายยังเป็นช่วงนั้น
- หากทำซับใหม่ ให้แยก transcript เต็มจากข้อความขึ้นจอ โหมด full เป็นค่าตั้งต้น; เมื่อผู้ใช้เลือก selective ให้ขึ้นเฉพาะสารสำคัญ/keyword ตามเพดานคำในโปรไฟล์ ข้าม filler คงคำปฏิเสธและเงื่อนไข แยกหมายเหตุ SOP ที่ต้องครบ ใช้ข้อความธรรมดาเป็นค่าเริ่มต้น; preset/animation ใช้เฉพาะที่บรีฟอนุญาตและตรวจทรัพยากรได้ งานซับละเอียดให้ capcut-subtitles รับโปรไฟล์เดียวกัน
- รักษา tracks/materials/drafts อื่นนอกขอบเขต สำรองก่อนเขียนทับตามปกติ เว้นแต่ผู้ใช้ระบุไม่ต้องสำรอง ตรวจ staging ก่อนแทนที่เสมอ

เมื่อแก้ QC การพูดซ้ำหรือได้รับ retake_groups อ่าน [สัญญาเลือกเทคของ planner](../capcut-story-planner/references/editorial-contract.md) ใช้ candidate ที่ครบสารและต่อเรื่องได้ตาม QC ตรวจ `content_review` ที่ผูกช่วงและรอยต่อล่าสุดก่อนสร้าง staging รวมการเริ่มสารเดิมข้ามคัต การถอดเสียงที่ลื่นไม่รับรองว่าพูดครั้งเดียว; timecode ของ QC เป็นจุดค้นหา ต้องย้อนหาต้นประโยคและขอบจริงก่อนตัด รักษาบริบทเฉพาะที่มาก่อนเทคที่ตัดและแยกไว้จากช่วงห้ามใช้

หากตัด CTA รอบลองพูด ให้รักษา CTA ที่เลือกเป็นประเด็นครบ พร้อมคำเชิญชวน/ภาพที่คำพูดอ้างถึง/ข้อมูลช่องทางซื้อจากสื่อเดิม และเสียงปิดที่กำหนด รีไทม์ซับและภาพช่องทางซื้อที่ยังจำเป็นตามหน้าที่ ไม่ลบทิ้งทั้งหมดเพียงเพราะเคยอยู่ทับเทคที่ถูกตัด

เมื่อ profile กำหนดหนึ่งบรรทัดและ shared anchor ให้ main/keyword ใช้ตำแหน่งอ้างอิงเดียวกันทุก cue ตรวจ Thai-shaped width, font/scale/spacing/กล่องจริง และเวลาที่อาจซ้อนกัน ย่อสารหรือแบ่ง cue ตามความหมายก่อนปรับขนาดอย่างอ่านง่าย เก็บ layout evidence ส่ง native read-back ผ่านสัญญาของ planner ห้ามใช้การไม่มี newline รับรอง auto-wrap และตรวจ animation ที่เคลื่อนตำแหน่งด้วย SOP คงครบแยกไว้

## 4. ตรวจ ส่งมอบ และใช้ซ้ำ

ตรวจความตรงบรีฟ ลำดับเรื่อง source/timeline ranges, units, media/material references, ภาพดำ/ช่องว่างที่ไม่ตั้งใจ, sync, volume/channel references, ซับที่เลื่อน และ diff นอกขอบเขต ใช้เวลาของ draft ที่ตรวจได้ ไม่ยก Premiere ticks มาใช้

ตรวจจาก draft ที่เขียนจริงว่า selected source/audio ไม่ชน excluded spans เสียงปิดถูกรักษาครบอยู่ท้ายเนื้อหาหลัก และไม่มี tail gap/overlay ค้างโดยไม่ตั้งใจ เปรียบเทียบ source→edited mapping และ cue/profile ไม่ใช้จำนวนคัตหรือ cue ตายตัวเป็นหลักฐานความถูกต้องของเนื้อหา

งาน QC เทคซ้ำต้องผ่าน validate_plan ที่เปิด require_content_review ก่อนส่งเข้า native verifier แล้วตรวจ retake_groups บนทุกแทร็กที่มีเสียงใน staging และ read-back หลังเขียน ผลผ่านแปลว่า draft ตรงกับการเลือกที่บันทึกไว้; รายงานความแน่ใจของความหมายและรอยต่อแยกจากผลตรวจไฟล์

ส่งพาธ draft/โฟลเดอร์โปรเจกต์ ชื่องาน ความยาวจริง รายการแก้ และสถานะตรวจ แยกการตรวจ JSON/สื่อออกจากการเปิดเล่นหรือ render จริงใน CapCut ซึ่งสกิลนี้ห้ามทำ พรีวิวภายนอกถ้าสั่งและทำได้ให้ระบุว่าเป็น external preview ไม่รับรอง native effects

เมื่อต้องใช้วิธีทำงานเดิมกับคลิปใหม่หรือเก็บเป็นซีรีส์ อ่าน [โปรไฟล์ที่ใช้ซ้ำได้](references/reusable-workflow.md) นำหลักการกลับมาใช้แต่เลือกสื่อและคำนวณเวลาใหม่ ไม่แก้ SKILL.md ตามฟีดแบ็กเฉพาะช็อต
