# Domain Docs

ใช้โครงสร้าง single-context สำหรับทั้งโปรเจกต์

## ก่อนสำรวจโค้ด

- อ่าน `GLOSSARY.md` ที่รากโปรเจกต์
- อ่าน ADR ใน `docs/adr/` ที่เกี่ยวข้องกับงาน

หากไฟล์เหล่านี้ยังไม่มี ให้ทำงานต่อโดยไม่ต้องแจ้งหรือเสนอให้สร้างล่วงหน้า
skill domain-modeling จะสร้างเมื่อมีคำศัพท์หรือการตัดสินใจที่ชัดเจนแล้ว

## โครงสร้าง

- `GLOSSARY.md`: คำศัพท์โดเมนของโปรเจกต์
- `docs/adr/`: บันทึกการตัดสินใจทางสถาปัตยกรรม

## ใช้คำศัพท์จาก glossary

เมื่อกล่าวถึงแนวคิดโดเมนในชื่อ issue ข้อเสนอ refactor สมมติฐาน
หรือชื่อ test ให้ใช้คำตาม GLOSSARY.md
หลีกเลี่ยงคำพ้องที่ glossary ระบุว่าไม่ใช้

หากไม่มีคำที่ต้องการ ให้พิจารณาว่าเป็นคำที่โปรเจกต์ไม่ได้ใช้
หรือเป็นช่องว่างที่ควรบันทึกไว้สำหรับ domain-modeling

## แจ้งเมื่อขัดกับ ADR

หากข้อเสนอขัดกับ ADR ที่มีอยู่ ให้ระบุหมายเลข ADR
พร้อมเหตุผลที่ควรทบทวนการตัดสินใจนั้นอย่างชัดเจน
